## Achados

### 1. ⭐⭐⭐ Contenção por relocação, e o que ela não alcança — impacto **A**, cap. 07

*"Every other marketplace plugin: Claude Code copies the plugin into `cache/<marketplace>/<plugin>/<version>/`
at install and loads that copy. Files outside the plugin directory aren't copied, so when a script inside a
copied plugin reads a path above the plugin root, such as `../shared`, it doesn't find them"*.

Este é um mecanismo que eu não tinha catalogado, e é o **décimo segundo** da taxonomia. Ele não checa o
caminho nem nega a leitura: **move o código para um lugar onde o alvo da fuga não existe.** Em 9/nov registrei
contenção por **remoção posterior**, quando o sandbox apaga `HEAD`, `objects` e `refs` criados na sessão;
esta é contenção por **relocação**, e é mais barata, porque não há o que verificar depois.

O que interessa mais é o que ela **não** alcança, e a página enumera: *"`--plugin-dir` and skills-directory
plugins: the directory loads in place and is never copied"*; plugin de caminho relativo em marketplace local
carrega no lugar; e *"`command`-source plugins in link mode: the directory the command printed loads in place,
through links in the cache entry"*.

A gradação é coerente — a proteção forte vale para a fonte menos confiável, o marketplace remoto, e não vale
para o que o operador apontou à mão. Mas o efeito acumulado dos últimos dias merece ser dito junto:
**o diretório `.claude/skills` é a superfície que carrega por leitura** (10/nov), **não é copiada** (hoje) e
**precisou de três correções de carregamento em cinco dias** — abaixo da pasta de partida, dentro de
`~/.claude/plugins` e dentro de plugins de `--plugin-dir`. Para o cap. 07, é a mesma observação de sempre num
caso concreto: a contenção mais forte está onde o risco é mais fácil de imaginar, e a superfície que mais
mexeu é a que nenhuma das duas contenções cobre.

### 2. ⭐⭐⭐ A lista de recusas, e a barra invertida recusada pela forma — impacto **A**, cap. 07

A frase que governa é *"Whether a plugin loads in place or from a cached copy, Claude Code doesn't let it
declare components outside its own directory. It rejects a component path that resolves outside the plugin
root, whether the path is declared in `plugin.json` or in a marketplace entry"* — e note que são **dois
lugares de declaração**, o manifesto do plugin e a entrada do marketplace, o que é o eixo da via de chegada de
7/nov aplicado à declaração.

São três formas recusadas. A literal: *"A path that points outside the plugin as written, such as
`../shared-utils`"*. A indireta, com a exceção declarada: *"A symlink that leads outside the plugin, other
than links between plugins within one marketplace"* — décima instância da família do symlink, e a primeira em
que a exceção é entre plugins **do mesmo** marketplace.

E a terceira é a que vale o achado: *"On macOS and Linux, a path that contains a backslash anywhere in it,
even when the path stays inside the plugin. Components declared with backslash paths therefore load on Windows
only, so write component paths with forward slashes, such as `./commands/deploy.md`"*.

Barra invertida **em qualquer lugar** do caminho é recusada, ainda que o caminho permaneça dentro do plugin. É
a decisão de **recusar em vez de interpretar**, que é a mesma escolha dos três remédios de nome enganoso de
10/nov, aqui com o custo declarado na própria frase: componente assim **carrega só no Windows**. O mesmo
plugin, a mesma declaração, dois comportamentos — e a documentação prefere essa assimetria visível a tentar
adivinhar o separador.

⏳ E registro a troca que a página escolhe sem discutir: *"A rejected path appears as a `path escapes plugin
directory` error, and the plugin loads without that component."* O plugin **carrega sem a peça recusada**, e o
plugin inteiro não é barrado. É defensável e é uma escolha: quem instalou um plugin de cinco componentes pode
acabar rodando quatro sem notar.

### 3. ⭐⭐ A limpeza com janela, e o varredor que só roda se houver instalação — impacto **B**, caps. 07 e 10

*"When you update or uninstall a plugin, Claude Code writes an `.orphaned_at` marker into the previous version
directory. It removes that directory in a background cleanup 14 days later, so a session that already loaded
the old version keeps running."*

A razão declarada é trabalho em voo: a versão antiga fica catorze dias **para que a sessão que já a carregou
continue rodando**. Depois de três semanas somando casos em que trabalho em voo morre numa fronteira — processo
órfão em quatro sistemas, thread descendente não restaurada no desarquivamento, agente concluído reexecutado na
retomada —, é a primeira vez que vejo a solução ser **atrasar a limpeza** em lugar de cancelar ou recuperar.
Vale como padrão no capítulo, ao lado da remoção posterior de 9/nov, porque são o mesmo mecanismo com sinais
opostos: ali apaga-se o que apareceu, aqui preserva-se o que vai sair.

E a frase seguinte tem um paradoxo que vale a linha: *"The sweep runs only while `installed_plugins.json`
records at least one install. After you uninstall your last plugin, orphaned directories stay until you
install another."* O varredor só roda enquanto houver algo instalado, de modo que **o estado mais limpo é o
único que não é limpo**. Não é falha de segurança e é bom exemplo de condição de guarda escrita do lado
errado — a limpeza foi presa à presença do que ela não limpa.
