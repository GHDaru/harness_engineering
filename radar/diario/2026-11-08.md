## Achados

### 1. ⭐⭐⭐ Uma regra só de precedência, e especificidade nunca vence — impacto **A**, cap. 07

A fila pedia para ler juntas o `any-source-true` de 7/nov, o `managed.policy_mode: layered` de 31/out e a
negação ampla vencendo pedido específico da v2.1.319. A página de permissões dá o princípio em uma frase:

*"Rules are evaluated in order: deny, then ask, then allow. The first match in that order determines the
outcome, and rule specificity doesn't change the order."*

A última cláusula é a resposta. Não é o mais específico que vence, é a **classe** que decide, e a ordem das
classes é fixa. O exemplo está na linha seguinte, e é o achado de 23/set documentado como desenho:
*"A broad deny rule like `Bash(aws *)` blocks every matching call, including calls that also match a narrower
allow rule like `Bash(aws s3 ls)`. An allow rule can't carve an exception out of a deny rule."*

As outras camadas seguem o mesmo sentido. Acima das regras estão os ganchos: *"A blocking hook also takes
precedence over allow rules. A hook that exits with code 2 stops the tool call before permission rules are
evaluated, so the block applies even when an allow rule would otherwise let the call proceed."* E a assimetria
do gancho é explícita, porque ele pode fechar em todo lugar e não pode abrir em todo lugar: *"In plan mode,
apart from `ExitPlanMode`, your `PreToolUse` hook's `"allow"` has no effect on a file edit or another call that
isn't read-only."*

No sistema de arquivos vale o mesmo, e a página de sandboxing diz com as mesmas palavras: *"If you add an
`allowWrite` entry or an `Edit` allow rule that covers one of these paths, the protection still applies."*

**Então formam regra, e a regra é esta: em toda camada, o valor restritivo vence, e especificidade nunca
compra precedência.** O `any-source-true` é a mesma ideia entre escopos de ajuste — o `true` restritivo vence
de qualquer fonte —, e o `layered` de 31/out é a exceção declarada como **modo**, porque troca primeiro-que-casa
por mescla.

O corolário interessa ao capítulo e ao operador: **quem escreve uma permissão mais específica esperando que
ela vença está escrevendo uma regra que não pode vencer.** As exceções conhecidas não são de especificidade,
são de alcance: a isenção de `--mcp-config` e a via de chegada que não recebe o ajuste, as duas de 7/nov.

### 2. ⭐⭐⭐ Duas coisas chamadas *deny*, com observabilidades diferentes — impacto **A**, cap. 07

*"Deny rules behave differently depending on whether they name a tool or scope a pattern within one. A bare
tool name like `Bash` removes the tool from Claude's context entirely, so Claude never sees it."*

A mesma palavra cobre dois mecanismos. Negar por **padrão** é portão no momento da chamada: o modelo tenta e é
barrado. Negar por **nome puro** é remoção da lista de ferramentas: o modelo não tenta, porque não sabe que
existe. Para a taxonomia do cap. 07 isso é distinção de primeira ordem, porque muda o que o modelo pode
sequer propor e muda o que aparece no traço — e em 7/nov vimos a assimetria oposta documentada no `blocked` de
organização, em que a ferramenta é filtrada antes de o modelo ver e o `/mcp` continua mostrando.

E há uma ferramenta que não se pode remover: *"Bare-name removal applies to every tool except
`EndConversation`: a deny rule can't remove it while any other tool remains, and an ask rule never prompts for
it."* Não se tira do agente a capacidade de encerrar. Vale como princípio de projeto, e é o primeiro caso que
registro de **ferramenta não negável por desenho**.

### 3. ⭐⭐⭐ A mesma lista de caminhos é três coisas ao mesmo tempo — impacto **A**, caps. 07 e 15

A seção *Protected paths* declara a ameaça que motiva a proteção, e ela é a de auto-escalada: *"Inside the
directories that sandboxed commands can write to, the sandbox still denies writes to the files Claude Code
loads configuration and code from. A command that could edit those files could grant itself permissions, or
add a hook or MCP server"*.

A lista, no diretório de trabalho e acima dele, é *"the `.claude` settings files, the `.claude/skills`,
`.claude/agents`, `.claude/commands`, and `.claude/hooks` directories, `.mcp.json`, and the files Claude Code
runs on its own"*. No diretório de trabalho apenas, entram *"shell startup files such as `.bashrc` and
`.zshrc`, `.gitconfig`, the `.vscode` and `.idea` directories, and `hooks` and `config` inside `.git`"*. E há
uma entrada que descreve um ataque em vez de um arquivo: *"Files that would turn your working directory into a
bare git repository: `HEAD`, `objects`, and `refs` at the top level"*.

O que fecha o raciocínio é juntar isso com os dois achados recentes. Em 2/nov, o paper de arquivo de memória
mostrou que quem pode alterar `CLAUDE.md` por um pull request dirige o agente. Em 7/nov, a correção foi
`--trust-workspace false` passar a impedir que **gancho e skill do repositório rodassem**. Hoje, a mesma lista
aparece como o que o agente **não pode escrever**. São três coisas distintas sobre o mesmo conjunto de
caminhos: **o que o agente não pode escrever, o que o harness não deve executar sem confiança, e o que o
atacante quer alterar.** O cap. 15 trata arquivo de instrução como memória; a lista diz que ele é superfície.

Duas ressalvas que a página declara e que valem mais que a proteção. A primeira é temporal, na família do
symlink que já tem seis instâncias: *"If a symlink appears at a protected settings file's path during the
session, the sandbox also denies writes to the file it points to, starting with the next command."* A proteção
alcança o alvo do link **a partir do comando seguinte**, o que deixa a janela do comando corrente. A segunda é
um ajuste que anula a garantia, dito sem rodeio: *"If you set `allowNestedUserNamespaces` to `true` on Linux
or WSL2, don't rely on protected paths: code from a sandboxed command can end up running outside the
sandbox."*

### 4. ⭐⭐ O custo do portão, numa moeda nova — impacto **B**, cap. 07

A conta das moedas do custo do portão ganha uma que não estava na lista: a proteção quebra operação de rotina
e a saída oferecida é sair da proteção.

*"`git merge`, `git checkout`, and similar commands fail with `unable to unlink old` when they need to replace
a file the sandbox denies writes to."* E a continuação: *"After the failure, Claude may offer to rerun the
command outside the sandbox."* Quem tiver `allowUnsandboxedCommands` em falso não recebe a oferta e roda o
comando à mão.

É o git outra vez, o que reforça a família de portadores fixada em 30/out, e aqui por um caminho novo: não é o
git alcançando algo, é o git sendo **impedido** por uma proteção correta, com o preço pago em atrito. A mesma
página mostra por que o worktree é caso especial, o que encosta no escape de sandbox de 7/nov: *"when the
working directory is a linked git worktree, the sandbox also allows writes to the main repository's shared
`.git` directory so commands such as `git commit` can update refs and the index."*

E uma linha de leitura que o capítulo deve citar porque contraria a intuição do leitor sobre o que um sandbox
faz: *"Default read behavior: read access to the entire computer, except certain denied directories. This
default still allows reading credential files, so protect credentials you don't want commands to read."*

### 5. ⭐⭐ A fronteira entre harness e modelo, escrita pelo fornecedor — impacto **A**, Leitura executiva

*"Permission rules are enforced by Claude Code, not by the model. Instructions in your prompt or `CLAUDE.md`
shape what Claude tries to do, but they don't change what Claude Code allows."*

É a tese central do livro numa frase de documentação de produto, e é a terceira formulação independente em oito
dias. Em 2/nov, o paper mediu que arquivo de memória malicioso muda o que o desenvolvedor fica sabendo e não
move a taxa de forma consistente. Em 5/nov, a página de MCP Events do OpenClaw: *"signatures do not make
payload text trusted instructions or grant additional tools."* Hoje, o canal de instrução declarado como
distinto do canal de permissão, pelo fornecedor do harness mais maduro do corpus.

Para a Leitura executiva: **o canal de instrução não é o canal de permissão**, e três fontes independentes
dizem isso em oito dias — uma medindo, uma documentando protocolo, uma documentando produto.
