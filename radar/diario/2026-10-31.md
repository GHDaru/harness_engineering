## Achados

### 1. ⭐⭐⭐ O comentário, lugar onde o valor não conta — impacto **A**, cap. 07

Três portões caíram hoje, em dois harnesses, pelo mesmo motivo estrutural.

O primeiro é do OpenClaw: *"Fixes IMAP sender checks accepting a spoofed message when a trusted address is
hidden inside nested comments in its From header."* A nota complementa: *"This applies when IMAP uses a
token tied to a particular sender to decide which email may reach your agent."* O endereço confiável estava
dentro de comentários aninhados no cabeçalho, e a checagem o aceitou. Vale notar o que esse portão decide:
**qual e-mail pode chegar ao agente** — é filtro de entrada, e o que está em jogo é a fonte de instrução.

O segundo é do mesmo release: *"Skill icons and required-tool metadata now load correctly when an inline
YAML value has a trailing comment."* A linha seguinte diz *"Quoted hash characters remain part of the
value."* O que não carregava era **metadado de ferramenta exigida** — a declaração que diz do que a skill
precisa — e o que a apagava era um comentário no fim da linha.

O terceiro é do Claude Code v2.1.316: *"Fixed PowerShell hooks not blocking on exit code 2 when the command
begins with a type cast, `param`, `using` or an attribute"*. É a segunda falha de código de saída 2 depois
de 23/out, e agora o gatilho é o **token de abertura** do comando. Aquela entrada concluiu, a respeito do
checador de Bash: *"O verificador falha uma vez por forma, não só uma vez por nome."* A conclusão acabou de
pousar no tratamento de código de saída do próprio gancho.

O mecanismo é um só, e é novo na taxonomia do cap. 07 — a décima entrada. Todo analisador tem regiões que
a gramática declara sem valor: um comentário, uma declaração de abertura, um `#` que não está entre aspas.
O mecanismo não é que o nome faltava na lista: é que a forma carregou o nome para além do analisador. Tese
para o capítulo: **o verificador lê uma gramática, e toda gramática tem lugares onde um valor não conta.**

### 2. ⭐⭐⭐ A fronteira do diretório de trabalho, reimplementada ferramenta por ferramenta — impacto **A**, caps. 07 e 09

Quatro casos, dois harnesses, um dia.

Claude Code v2.1.316: *"Fixed `--restricted` sessions uploading files from outside the working directories
when a Read allow rule covered them"*. Uma regra de permissão de **leitura** produziu um **envio**. O eixo
de precedência de 23/set e 28/set aparece invertido: ali a negação por grupo venceu a permissão explícita;
aqui a permissão explícita venceu o modo restrito, e o efeito saiu por uma operação diferente da autorizada.

OpenClaw: *"Workspace-only restrictions now apply to Gateway-built delegation and media tools, so restricted
setting changes require approval and media reads stay within the allowed folders."* A restrição de espaço de
trabalho não alcançava as ferramentas que o próprio Gateway constrói. A nota preserva a exceção:
*"Explicit policy overrides and read-only attachment exceptions retain their existing behavior."*

OpenClaw, ainda: *"New ACP sessions now run tools in the project folder you requested, including after a
session reset, instead of silently using the default workspace."* O advérbio é o achado — **silently**. O
recuo para o espaço padrão não avisava. E a pasta da sessão ACP faz parte da identidade da sessão, o que
encosta no caso 29 da série dos dois leitores, de 29/out, em que a sessão ACP se resolvia sem id exato.

E o quarto: *"Images sent while steering an active Codex turn now resolve from that session's workspace,
rather than incorrectly accepting a shared-workspace image or rejecting the intended one."* A nota localiza
a condição: *"This repairs the session-scoped image path when `tools.fs.workspaceOnly` is false."*

O contra-lance veio na mesma janela, na v2.1.314: *"Added `permissions.blockWritesOutsideWorkingDirectories`:
Write, Edit and NotebookEdit refuse paths outside the working directories in every permission mode"*. O que
distingue esse controle é a cláusula final — vale em **todo** modo de permissão, e boa parte do que este mês
levantou foi justamente lacuna que dependia do modo.

Leitura para os capítulos: a fronteira do diretório de trabalho não é uma fronteira; é uma fronteira
reimplementada em cada ferramenta que a atravessa. Cada ferramenta nova é uma oportunidade de reimplementá-la
errado, e quatro casos num dia medem o tamanho dessa oportunidade.

### 3. ⭐⭐⭐ A redação alcança o olho, e o modelo fica de fora por escrito — impacto **A**, cap. 08

O mesmo release do OpenClaw traz duas redações de credencial com **alcances diferentes**, e diz quais são.

A primeira: *"MCP command-line inspection now hides recognized credentials instead of exposing them in
terminal output and captured transcripts. Scripts reading these inspection results receive redaction
placeholders rather than secret values."* O alcance inclui o leitor programático, que é o alcance certo.

A segunda: *"Google sign-in client secrets are now masked in console and log-tail output. Raw local log
files and model-visible tool output are unchanged."* A proteção alcança o console e a cauda do log, e para
antes do arquivo bruto e antes da saída que o modelo vê. Está escrito na própria nota.

É o caso mais nítido até agora da tese de 19/out, **a garantia vale até onde a observação alcança**, com o
sinal trocado: ali a garantia parava onde a observação parava; aqui a **proteção** para onde o olho do
operador para, e o canal que o agente lê fica explicitamente fora. Duas redações no mesmo release, com dois
alcances, dão o critério para o cap. 08: a nota de uma redação precisa declarar **quais leitores** ela cobre,
e saída visível ao modelo é um leitor.

### 4. ⭐⭐ O que o sistema não fez é informação — impacto **A** na Leitura executiva, **B** no cap. 05

Cinco linhas de três sistemas, no mesmo eixo.

OpenClaw: *"Command errors now preserve warnings when OpenClaw cannot confirm that process cleanup finished,
along with the command output and exit details."* E: *"Video-generation results now show options that the
provider ignored, in both text and JSON output."* E ainda, sobre escrita retomada depois de liberar disco:
*"Interrupted writes are not automatically replayed."*

opencode v1.19.5, único item do release, atribuído no bloco de contribuidores ao
[#54936](https://github.com/anomalyco/opencode/pull/54936):
*"Failed TUI worker requests now return an error instead of leaving the caller hanging."*

Claude Code v2.1.316: *"Fixed shell commands being left running on macOS and Linux when Claude Code exits by
itself, for example when credentials are refused or a cloud session is archived"*.

O paper de exatamente-uma-vez, lido em 28/out, mediu que **80%** dos episódios que produziram duplicata
terminam como *completed* sem listar incerteza, com superdeclaração em **90% (78–96%), n=1.279**. Aqui um
harness publica uma mudança cujo conteúdo inteiro é **preservar o "cannot confirm"**. O paper mediu a
ausência; este release nomeia a coisa e a guarda. A linha das opções ignoradas pelo provedor é da mesma
família: o sistema relata o que foi pedido e não aconteceu.

As outras três são trabalho em voo quando algo falha. O OpenClaw declara não-reexecução em texto, o opencode
troca espera indefinida por erro, o Claude Code deixa de órfãos os processos quando ele mesmo sai. Um eixo,
três sistemas, um dia — e é o eixo que o cap. 05 discute quando fala de contrato de ferramenta.

### 5. ⭐⭐ Aprovação com geração, e política que compõe — impacto **B**, caps. 07 e 12

Quatro itens menores que mexem em teses abertas.

**Aprovação presa a uma geração.** OpenClaw: *"Connected nodes no longer disconnect when you reapprove their
capabilities while a command is being prepared."* Com a ressalva: *"Commands approved under the previous
pairing generation remain refused."* Isso dá a quinta propriedade da lista de aprovação-como-objeto, depois
de atribuível a um portador, autenticável na volta e saber quem tem autoridade para dar: a aprovação
pertence a uma **geração**, e renovar o pareamento a anula. O defeito corrigido é o preço disso — reaprovar
derrubava o nó com comando em preparo, o que acrescenta uma sexta moeda ao custo do portão: a janela de
revogação mata trabalho em curso.

**Política que compõe.** Claude Code v2.1.316: *"Added `managed.policy_mode: layered` to the Claude apps
gateway: every policy that matches a developer applies, each merged over the ones listed below it, not only
the first"*. A leitura do que havia antes está na própria frase: entre várias políticas gerenciadas que
casavam, só a primeira valia. Entra na linha de precedência de 23/set e 29/out, e com uma ressalva — é um
**modo**, então o comportamento anterior segue sendo o padrão de quem não o liga.

**A escolha ausente, terceira vez.** Duas linhas da v2.1.316 sobre o mesmo sentinela: *"Fixed a managed
`autoMode.allow` list without `"$defaults"` getting the built-in exceptions back from a host app's
`--settings`, a first rule added in `/permissions`, or `/auto-mode-setup`"* e *"Changed auto mode so that an
`autoMode.allow` list without `"$defaults"` no longer removes the built-in rule on scheduled-task prompts"*.
A lista sem o sentinela recuperava as exceções embutidas por **três portas distintas**, e removia a regra
embutida onde não devia. O mecanismo da escolha vazia ou ausente aparece pela terceira vez no mês.

**O valor explícito perdido para a configuração herdada.** OpenClaw: *"Remote Gateway probes now respect an
explicitly requested SSH port 22 instead of switching to the port configured for an SSH alias."* Com a
fronteira declarada: *"Targets without an explicit port still use their SSH configuration."* Isto fecha com
instância o item 1 da fila de 30/out: o critério do cap. 05 de que ferramenta externa seja invocada com
**ambiente explícito** ganha um caso em que o valor pedido perdeu para o alias — e perdeu porque o valor
pedido **era** o padrão, logo não se distinguia de ausência. A proposta ao editor está formulada e aguarda
decisão dele; não avanço o texto do capítulo.
